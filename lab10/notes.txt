Lab 10 - Add Your Own System Call: trace
Lucian-Adrian Gavril, FAF-241. xv6 = upstream mit-pdos/xv6-riscv plus lab10.patch.

Check 1: "3 trace: unknown sys call 23" then "trace: failed"   (a7 = 23 reached the kernel)
Check 2: trace 32 grep hello README -> read 1023, 965, 453, 0   (1023+965+453 = 2441 = size of README)

1. Why only read, and not open or close?
   The mask is 32 = 2^5, so only bit 5 is on, and 5 is SYS_read. syscall() prints only when
   (p->trace_mask >> num) & 1 is 1. For open (15) and close (21) that bit is 0, so those
   calls run normally but are not printed. With mask 2147483647 (all bits on) the same
   command shows trace, exec, open, read x4 and close.

2. In forkforkfork several pids print lines. Which line makes that possible?
   The line in fork() (kernel/proc.c):  np->trace_mask = p->trace_mask;
   Every child starts with its parent's mask, so the children and grandchildren that call fork
   also print. My run showed pids 6, 7, 8, 9, 10 and 11, up to fork -> 67 and then -1 when the
   process table (NPROC = 64) was full.

3. In trace 65536 echo hi, why is the trace line printed between "hi" and the newline?
   echo calls write twice: write(1, "hi", 2) for the argument, then write(1, "\n", 1).
   The kernel prints the trace line after each call returns, so the order on the console is:
   "hi", "68: syscall write -> 2", "\n", "68: syscall write -> 1".

4. Which mask traces both open (15) and close (21), and nothing else?
   2^15 + 2^21 = 32768 + 2097152 = 2129920.
   trace 2129920 grep hello README  -> "open -> 3" and "close -> 0" only.

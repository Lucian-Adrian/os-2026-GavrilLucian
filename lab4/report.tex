\utmintroduction
\textbf{Purpose of the work.} To use the xv6 shell (\texttt{user/sh.c}, 499 lines) side by side with Bash and find out by experiment what a shell must do and what Bash adds on top. To show with a small program, \texttt{args}, who expands \texttt{*} and who removes quotes. To bring the \texttt{sleep} program from Lab 2 up to date with the current xv6, where the system call \texttt{sleep()} has been renamed \texttt{pause()}.

\textbf{Environment.} Debian GNU/Linux 13, GNU Bash 5.2.37, GCC 14, \texttt{riscv64-linux-gnu} toolchain, QEMU 10 (\texttt{qemu-system-riscv64}). xv6 is the current upstream \texttt{mit-pdos/xv6-riscv} in \texttt{\~{}/xv6-riscv} (commit \texttt{e93dabe}), to which \texttt{user/sleep.c} and \texttt{user/args.c} were added. Each QEMU session started from a freshly built \texttt{fs.img}. Every terminal figure is the real output of the commands shown in it.

\chapter{Fix sleep for the current xv6}

\section{Which name does the tree use?}
\texttt{grep -n "pause\textbackslash|sleep" user/user.h} prints a single line, \texttt{25:int pause(int);}, so this tree uses the new name and has no \texttt{sleep()} declaration at all (Figure~1.1). The matching stub is \texttt{entry("pause")} in \texttt{user/usys.pl}. A \texttt{sleep.c} that still calls \texttt{sleep()} therefore fails at link time with \texttt{undefined reference}: declaring a prototype in \texttt{user.h} is not enough, because a system call also needs the assembly stub that \texttt{usys.pl} generates and the kernel table entry in \texttt{syscall.c}.
\shot{fig1_1_grep_user_h.png}{The grep result in user.h}

\section{The updated sleep.c}
The program checks that exactly one argument is given; otherwise it prints the usage line on stderr (fd 2) and exits with status 1. It then converts the argument with \texttt{atoi()} and calls \texttt{pause()}. \texttt{\$U/\_sleep\textbackslash} and \texttt{\$U/\_args\textbackslash} are in \texttt{UPROGS}; \texttt{cat -A} shows that each line starts with a real TAB (\texttt{\^{}I}) and ends with the backslash, with nothing after it (Figure~1.2).
\shot{fig1_2_sleep_c.png}{The updated sleep.c and its UPROGS line}

\section{Running sleep in xv6}
After \texttt{make qemu}, \texttt{sleep 20} returned to the prompt after 1.97~s of wall time. xv6 programs the timer interrupt every 1\,000\,000 cycles of the 10~MHz QEMU clock, i.e.\ one tick every 0.1~s, so 20 ticks $\approx$ 2~s, as expected. Without an argument the program prints \texttt{usage: sleep <ticks>} (Figure~1.3).

\section{Answers to the Observe questions}
\begin{utmenumerate}
\item \textbf{Features both shells have, and the ones only bash has.} Both: running a program with arguments, \texttt{<} and \texttt{>} redirection (xv6 also has \texttt{>>}), pipes \texttt{|}, sequences \texttt{;}, background \texttt{\&}, grouping \texttt{( )}, and the built-in \texttt{cd}. Only Bash: globbing (\texttt{* ? [ ]}), variables and the environment (\texttt{\$HOME}), quoting (\texttt{" "}, \texttt{' '}, \texttt{\textbackslash}), PATH search, history, Tab completion, Ctrl+R, \texttt{\&\&} and \texttt{||}, job control (\texttt{jobs}, \texttt{fg}, \texttt{kill \%1}), command substitution, and scripting (\texttt{if}, \texttt{for}, functions).
\item \textbf{Why does ls stop working after cd d, and how can it still be run?} xv6 has no PATH: \texttt{exec("ls", ...)} opens \texttt{ls} relative to the current directory. All xv6 programs live in the root directory \texttt{/}, where \texttt{mkfs} put them, so the bare name works only while the current directory is \texttt{/}. Inside \texttt{d} it gives \texttt{exec ls failed}. A path to the program works: \texttt{/ls} (absolute) or \texttt{../ls} (relative). Both list \texttt{d}, and \texttt{/echo} works the same way (Figure~2.3).
\item \textbf{What would I miss most, and what is easiest to add?} I would miss globbing with quoting the most, together with history and Tab completion, because every file name would have to be typed in full. The easiest to add is a PATH fallback: when \texttt{exec(argv[0])} fails and the name has no \texttt{/}, \texttt{runcmd()} can retry \texttt{exec} with \texttt{"/"} prepended. That is about five lines in \texttt{case EXEC} and needs no new data structures.
\end{utmenumerate}

\section{Answers to the Observe questions}
\begin{utmenumerate}
\item \textbf{Both outputs for args *.c "x y", and how many arguments each program received.}

\begin{minipage}[t]{0.47\linewidth}\textbf{bash} -- \texttt{argc = 5}
\begin{verbatim}
argv[0] = [./args]
argv[1] = [a.c]
argv[2] = [args_linux.c]
argv[3] = [b.c]
argv[4] = [x y]
\end{verbatim}\end{minipage}\hfill
\begin{minipage}[t]{0.47\linewidth}\textbf{xv6} -- \texttt{argc = 4}
\begin{verbatim}
argv[0] = [args]
argv[1] = [*.c]
argv[2] = ["x]
argv[3] = [y"]
\end{verbatim}\end{minipage}

The Linux program received 4 arguments after its name: \texttt{*.c} became three file names, and \texttt{"x y"} became one argument without the quotes. The xv6 program received 3: the literal \texttt{*.c}, and \texttt{"x y"} cut at the space into \texttt{"x} and \texttt{y"}, with the quote characters still present.
\item \textbf{Who turns *.c into file names and removes the quotes?} The shell. It is the same \texttt{exec} system call on both systems, and the program code is the same. Only the shell differs, and the results differ with it. The kernel copies the strings it is given onto the new process's stack, and the program prints what it receives. Bash expands and removes quotes before \texttt{execve()}; the xv6 shell does neither. The other two lines confirm this: \texttt{args \$HOME} gives \texttt{/home/dev1} in Bash and the literal \texttt{\$HOME} in xv6, and \texttt{'single quoted'} is one argument in Bash but two (\texttt{'single} and \texttt{quoted'}) in xv6.
\item \textbf{What happened to the extra spaces in one two three?} Both shells used them only as separators: \texttt{argc = 4} with \texttt{[one] [two] [three]}. The xv6 tokenizer \texttt{gettoken()} skips any run of characters from \texttt{whitespace[] = " \textbackslash t\textbackslash r\textbackslash n\textbackslash v"}, and Bash word splitting does the same. To keep the spaces in Bash the argument must be quoted (\texttt{"one   two"}); in xv6 they cannot be kept at all.
\end{utmenumerate}

\section{How sh.c runs a line}
\texttt{main()} reads a line with \texttt{getcmd()}. If the line is not \texttt{cd}, it calls \texttt{fork1()}, and the child runs \texttt{runcmd(parsecmd(buf))} while the parent waits. \texttt{parsecmd()} is a recursive-descent parser (\texttt{parseline}, \texttt{parsepipe}, \texttt{parseexec}, \texttt{parseredirs}, \texttt{parseblock}) that builds a tree of command structures. The switch at lines 75--125 executes each node; the second switch, at lines 469--493, in \texttt{nulterminate()}, only puts \texttt{'\textbackslash0'} after each word. The character switch at lines 284--297 in \texttt{gettoken()} defines the only special characters: \texttt{| ( ) ; \& < >} and \texttt{>>} (returned as \texttt{'+'}).

\section{Answers to the Observe questions}
\begin{utmenumerate}
\item \textbf{The five kinds of command and the character that produces each} (lines 8--12, Figure~4.1):
\texttt{EXEC} (1) -- a plain command with no operator, run with \texttt{exec()};
\texttt{REDIR} (2) -- \texttt{<}, \texttt{>} and \texttt{>>}: closes fd 0 or 1 and opens the file, which then gets the lowest free fd;
\texttt{PIPE} (3) -- \texttt{|}: \texttt{pipe()}, two \texttt{fork1()} calls, each child replaces fd 1 or fd 0 with an end of the pipe;
\texttt{LIST} (4) -- \texttt{;}: fork and wait for the left side, then run the right side;
\texttt{BACK} (5) -- \texttt{\&}: fork and do not wait.
Parentheses do not form a sixth kind: \texttt{parseblock()} only groups other nodes.
\item \textbf{Where is cd handled, and why is it not a separate program?} In \texttt{main()}, lines 166--171 (Figure~4.3): if the line starts with \texttt{cd} followed by a space, the parent shell itself calls \texttt{chdir(cmd + 3)} and never forks. The comment in the source says ``Chdir must be called by the parent, not the child.'' The current directory belongs to each process: a child's \texttt{chdir()} would end with the child and leave the shell unchanged. This also explains \texttt{exec cd failed} in Part~2: inside a list the line does not start with \texttt{cd}, so \texttt{cd} is sent to \texttt{exec}, and there is no program with that name.
\item \textbf{Code that handles * or \$, and what that explains about Part 2.} There is none (Figure~4.4). \texttt{grep} finds no \texttt{'*'} character constant. The only \texttt{\$} in the file is the prompt string \texttt{write(2, "\$ ", 2)}, and there is no \texttt{getenv}, \texttt{HOME}, \texttt{PATH} or glob code. The special characters are only \texttt{symbols[] = "<|>\&;()"}. So \texttt{*}, \texttt{\$} and \texttt{"} are ordinary word characters for xv6, which is exactly why \texttt{ls *}, \texttt{echo \$HOME}, \texttt{echo "a b"} and \texttt{args *.c "x y"} behaved literally in Parts 2 and 3.
\end{utmenumerate}

\utmconclusions
A complete shell fits in 499 lines because the core is small: read a line, parse it into a tree of five node kinds, then \texttt{fork}, rearrange file descriptors and \texttt{exec}. Redirection, pipes, sequences, background jobs and grouping all worked the same way in xv6 as in Bash, because they are built only from \texttt{fork}, \texttt{exec}, \texttt{pipe}, \texttt{dup}, \texttt{close} and \texttt{wait}. The only built-in is \texttt{cd}, because it has to change the state of the shell process itself.

Everything else that Bash adds is user convenience implemented in the shell, not in the kernel: globbing, variables, quoting, PATH search, history and completion. The \texttt{args} experiment showed this directly. With the same system call and the same program, only the shell changed, and \texttt{argc} went from 4 to 5 and \texttt{"x y"} from two broken words to one clean argument. The xv6 failures (\texttt{ls: cannot open *}, \texttt{exec ls failed} after \texttt{cd d}, \texttt{exec cd failed} inside a list) each match a specific missing feature in \texttt{sh.c}.

Part~1 showed that a system call is a contract with three parts: a declaration in \texttt{user.h}, a stub generated from \texttt{usys.pl}, and a kernel table entry. Renaming \texttt{sleep} to \texttt{pause} broke old programs at link time, not at compile time. After the fix, \texttt{sleep 20} took 1.97~s, which matches the 0.1~s xv6 timer tick.
